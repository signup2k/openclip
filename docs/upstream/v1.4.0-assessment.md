## 优先考虑的修复

1. **粘贴探测饥饿恢复（#37 / #66）**：评估时本地 PasteAvailabilityProbe 使用单个 probe-slot，
   且等待阻塞 worker 返回才释放；一旦目标应用卡住，之后的探测可能持续返回 unknown。
   上游改为最多四个并发探测，超时即释放许可，并给菜单遍历增加总 deadline。
   这是与当前稳定性目标最相关的补丁。它主要影响“是否可粘贴”的判断和投递降级，
   不能声称它单独解决所有菜单不弹出的问题。
2. **开发脚本启动正确产物（53813da）**：评估时本地 dev_run.sh 从多个 DerivedData 目录中取第一个，
   可能构建了新代码却运行旧应用。应采用固定 derivedDataPath 或精确 build settings 路径；
   package_app.sh 有相似路径选择方式，也应一起修复，避免继续使用模糊 glob 兜底。
3. **Show Icon 持久化（f5eb220）**：Copy/Cut/Paste 等默认文本 glyph 动作切换为图标后，
   编辑器重开时可能回到文本模式，或未保存可解析的 symbol。上游加入显示模式推导和 builtin
   preferenceIconName 回退，可以按函数及测试移植。
4. **动作编辑器意外关闭（#61）**：列表更新不再每次 reloadData，避免重建承载 popover 的行；
   后续还引入独立 ActionSettingsPopover。应分离提取，并检查外观/启用状态变化时是否仍正确刷新。

## 独立维护安排（本次已落实）

- 本地显示版本从 1.0.0 开始，build number 从历史的 8 递增到 9，避免复用旧构建编号；
  这不代表已打 tag 或已发布。
- 移除上游 SUFeedURL 和 SUPublicEDKey；没有明确的个人 feed 和签名公钥时不启动 Sparkle，
  即使用户此前保存过自动更新偏好也不会触发上游检查。
- Release 脚本只构建手动安装 ZIP/DMG；工作流仅手动构建并保存 artifacts，不自动发版、
  生成上游 appcast 或更新上游 Homebrew tap。
- 本地仓库、问题入口和开发文档链接指向 signup2k/openclip，保留原项目许可与来源说明。
- 历史 v* Git tags 和历史上游 changelog 保留。将来个人 tag 使用 personal-v*，
  应用版本仍为普通 1.0.0；不覆盖已有的上游 v1.0.0 tag。
- 保留 upstream 远端供人工评估。扩展目录服务作为第三方内容来源保持兼容，
  不等同于主应用版本或自动更新绑定；本次不更换扩展来源。

后续顺序：先导入探测恢复、精确产物路径和小范围设置修复，再独立评估 diff/tooltip，
最后考虑快捷键及模态卡片行为。每批记录来源提交与验证结果。
